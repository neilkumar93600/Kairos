# WP-19 frontend hand-off: resume export

`GET /api/resumes/:id/export?format=pdf|txt` is live (session, same as the rest of `/api/resumes`).

| Answer | Meaning | What the web does |
|---|---|---|
| 200 | The file, `attachment`, `no-store`, with a safe file name in `Content-Disposition` | Save it |
| 404 `not_found` | Missing or not this user's | The usual not-found |
| 400 `invalid_param` | `format` is not pdf, docx or txt | A bug; never shown |
| 429 `rate_limited` | Over 20 exports a minute | "Try again in a minute" |
| 503 `service_unavailable` | `details.reason` is `render_failed` or `format_unavailable`, or the worker is busy past 25 s. `Retry-After: 5` | The browser print, with the PRD 7.4 notice that the file came from the browser |

Nothing else changed for the web. `format=docx` stays 503 until WP-39.

Known limit worth showing in the UI when you touch this: a resume with Chinese, Japanese or Korean text cannot be rendered yet, so export falls back to print, and a cloud send fails with "render_failed" and no charge.

The extension gets no change: `resumePdfUrl` is optional on the frozen `FillPayload`, and the filler already reads it.
