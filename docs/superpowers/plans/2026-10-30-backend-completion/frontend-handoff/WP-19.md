# WP-19 frontend hand-off: resume export

`GET /api/resumes/:id/export?format=pdf|txt` is live (session, same as the rest of `/api/resumes`). **The web does not call it yet**: `workspace.tsx` `download()` is `window.print()`.

## New web work

1. **A download button** that calls the route with `format=pdf`, and a "Copy as text" or `.txt` download with `format=txt`.
2. **A 503 falls back to `window.print()`**, with the PRD 7.4 notice that the file came from the browser.
3. **A 429** shows "Too many downloads. Try again in a minute."
4. **Resend copy for the cloud**: a cloud resend can now answer 409 `not_approvable` with `details.reason` set to `render_mismatch`, `render_too_large`, `render_output_too_large`, `render_bad_document` or `resume_missing`. Show the message and offer the extension instead. The failed application's `failureReason` already carries the matching copy.

## Answers

| Answer | Meaning | What the web does |
|---|---|---|
| 200 | The file, `attachment`, `no-store`, with a safe ASCII file name in `Content-Disposition` | Save it |
| 404 `not_found` | Missing or not this user's | The usual not-found |
| 400 `invalid_param` | `format` is not pdf, docx or txt | A bug; never shown |
| 429 `rate_limited` | Over 20 exports a minute | The message above |
| 503 `service_unavailable` | `details.reason` is `render_failed`, `invalid_document` or `format_unavailable`, or the worker is busy past 25 s. `Retry-After: 5` | Print, with the notice |

`format=docx` stays 503 until WP-39.

Known limit: the PDF fonts have no Chinese, Japanese, Korean, Devanagari or emoji glyphs. Such a resume exports through print, and a cloud send to a job board with a resume field fails with its own message and no charge.

The extension gets no change.
