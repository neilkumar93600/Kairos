## 2. `403 origin_not_allowed` on cross-site writes

A `POST`, `PUT`, `PATCH` or `DELETE` under `/api` (except `/api/auth/*` and `/api/webhooks/*`) that carries the session cookie must come from `WEB_ORIGIN` or an origin listed in `CSRF_ALLOWED_ORIGINS`. Without an `Origin` header, `Sec-Fetch-Site: same-origin` or `none` is accepted. Anything else answers:

```
HTTP 403
{ "error": { "code": "origin_not_allowed", "message": "This request came from a site Kairos does not trust", "details": { "origin": "<the Origin header, or null>" }, "requestId": "..." } }
```

The web calls `/api` with `fetch` from its own origin through the rewrite, so browsers send a matching `Origin` and nothing changes. Two things to keep in mind:

- **Vercel previews.** A preview deployment's origin must be listed in `CSRF_ALLOWED_ORIGINS` on the api it talks to (the same list Better Auth already needs for sign-in), or every save from that preview is 403. This is an env value, not a code change.
- Never call the API's write routes from server code (a route handler or server action) with a forwarded cookie: such a request has no `Origin` and is refused. The extension is unaffected: it sends a bearer token, which skips the check.

`ApiError` already carries `status` and `code`; showing `err.message` is enough.

## 3. `Cache-Control: private, no-store` on every signed-in answer

Every route behind sign-in now sends `Cache-Control: private, no-store`, errors included. React Query is unaffected (it never used the HTTP cache for these). The browser no longer keeps these answers on disk, so a back button after sign-out cannot show the previous user's data from cache.

## 4. Links must be http(s)

| Route | Field | New answer |
|---|---|---|
| `PUT /api/resume` | `contact.links[]` | A bare host (`github.com/ada`) or an `http(s)://` link is accepted as before. Any other scheme (`javascript:`, `data:`, `mailto:`) is `422 invalid_body`; the issue has `path: ["contact", "links", <i>]` and `message: "Links must be web addresses (http or https)"`. |
| `POST /api/jobs/import` | `url` | A non-http(s) URL is now `422 invalid_body` instead of `422 unsupported_board`. `job-url-import.tsx` checks `SUPPORTED_BOARD` before sending, so the web never sends one. |
| Resume-suite routes (`POST /tracker` `url` and `manual.url`, contacts `linkedinUrl`) | same `httpUrl()` rule in `shared/src/schemas-suite.ts` | `422 invalid_body` for anything but http(s). |

Suggestion for the resume editor's Links field (`components/resume/editor.tsx`): on a `422 invalid_body` whose first issue's `path[1] === "links"`, show that issue's message next to the field rather than the generic "Some fields are invalid".
