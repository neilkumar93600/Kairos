# WP-21 frontend hand-off

The tracker API is real now, on the contract you built against in `shared/src/schemas-suite.ts`. Differences from the mock, then what the web still has to build.

## Where the real API differs from the mock

- **Cards move up to a minute late.** Automatic moves come from a job that runs each minute. After a submission or reply, the card may still show the old stage for that long. A user's own move is immediate.
- **A sent application can go back to Applied, and a draft or failed one to Drafting.** The mock always refuses these (`409 approve_in_review_queue`). The real API refuses them only when the status disagrees, so a mis-drag can be undone. Applied while approved or submitting is still refused. Don't hide these drop targets by stage alone: try the PATCH and show the error's `message`.
- **`sendFailedRefunded` is false for an ambiguous failure** (`unconfirmed`, `timeout`, `no_report`), where the mail may have gone. Show the application's own failure text there, not "Send failed, credit refunded".
- **Lists page.** `GET /tracker`, `/contacts`, `/interviews`, `/tracker/:id/events` and `/applications/:id/events` take `?limit&cursor` and return the first 200 by default. `nextCursor` is absent on the last page; it is never null.
- **`salaryText` is null on list rows.** Read it from `GET /tracker/:id`.
- **`position`** must match `^[0-9A-Za-z]{1,64}$`, or the PATCH is 422. Use `positionBetween(before, after)` from `@auto-career/shared` for a drop: pass the neighbours' keys, null at a column's end.
- **More errors:** `409 limit_reached` at 5,000 cards or contacts, or 100 interviews on a card; `422 invalid_body` for an unknown time zone.
- **`GET /tracker` is paged.** Over 200 cards, follow `nextCursor`. A cursor belongs to its view: a board cursor is `400 invalid_param` on the table view, so drop it when the view changes.
- **`POST /tracker { url }`** is the import route's work: it spends a `jobImports` unit and goes through the AI limiter. It can answer `429 rate_limited` (`details.reason` `daily_allowance` or the burst limit), `422 unsupported_board`, `404 posting_not_found` and `503 service_unavailable`. `{ matchId }` and `{ manual }` do none of that.
- **The insights funnel** counts cards created in the range, not archived, by their stage now. The mock now does the same, and its 30-day case has a null median.
- **Timeline payloads** carry more than the `applicationEventSchema` comment lists: `reply_routed` also has ids and codes such as `inboundEmailId`, `linkedBy`, `source` and `rulesVersion`, and there's no `sender`. Ignore keys you don't know.
- **Mock only:** `POST /__mock/pipeline` moves a card at once, and its `failed` event logs a separate `refunded` row; the real timeline has no `refunded` kind, so show the refund wording from `sendFailedRefunded`.

## New: a Closed card stops a send

Approving or resending a job whose card is Closed no longer goes through, so a user never closes a job Kairos then applies to. `POST /applications/approve` lists it in `skipped[]` with reason `card_closed`; `POST /applications/:id/resend` answers `409 not_approvable` with `details.reason: "card_closed"` and a message to show. Tell the user to reopen the card, then offer the approve again. Reopening is any drag out of Closed.

## To build

- `/tracker` with board, table, tabs and the keyboard "Move to..." path (same PATCH); `/tracker/[itemId]`; `/applications` redirects to `/tracker?view=table`.
- **A stage set by mail.** `GET /api/applications/:id/events` (oldest first; `/tracker/:id/events` is newest first) has `reply_routed` rows whose payload carries `replyKind`, `stageChanged`, `stageHeld` and `authenticated`. When `stageHeld` is true the reply did not move the stage: say so. For a stage mail did set, offer undo: `POST /api/applications/:id/stage/clear`. The card follows within a minute, and only if the user hadn't chosen its stage themselves.
- **"Add {sender} from {company} as a contact?"** One click on a routed reply: `POST /contacts` with the sender's name. The sender comes from `GET /api/inbox?applicationId=`, not the event. Never automatic.
- **"This reply mentions an interview. Add the date?"** Shown from a `reply_routed` row with `replyKind` `interview` or `assessment`. Kairos never guesses the date; `POST /tracker/:id/interviews` needs `startsAt` and `timeZone`.
- **Insights.** `lowSample` true or a null rate means show counts only; `medianDaysToFirstReply` is also null below 5 sent. On Free and Starter the API answers `403 forbidden` with a message naming the plans; show the locked state.
- The `resumes` library's `stage` is now filled for tailored copies with a card.
