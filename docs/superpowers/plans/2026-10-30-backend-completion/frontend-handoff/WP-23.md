# WP-23 frontend handoff: job import

No file in `web/` was edited. The frozen web keeps working: every response shape below is one the type in `web/hooks/use-jobs.ts` already allows. Items 1 and 2 are needed to reach new behaviour. Items 3 and 4 are for information. Item 5 applies to any admin screen built on the new route.

## 1. The browser check blocks Lever EU (needs web work)

`SUPPORTED_BOARD` in `web/hooks/use-jobs.ts` omits `jobs.eu.lever.co`, so a Lever EU link never reaches the server, though the server now reads it. The minimum fix is one line: add the host, and a case to `web/test/resume-guards.test.ts`. Item 2 is the better fix and covers this too.

## 2. The browser check blocks employer links and the review queue (recommended: send every https link)

The same regex refuses any other host before a request is sent. So these never reach the server from the frozen web:

- an employer page carrying `?gh_jid=`, which the server can now resolve when a company row names that domain;
- the `board_requests` row that an unsupported link would otherwise queue for the owner, so the queue stays empty.

**Recommended (Contract review):** send every `https://` link to `POST /api/jobs/import` and let its 422 `unsupported_board` carry the message. The existing error handling already shows that code. A refused link gives the jobImports allowance unit back.

## 3. `fit.passed` now also means "at or over the bar"

`POST /api/jobs/import` runs the gate, then one scorer call, then the bar:

| Case | `fit` | `matchId` |
|---|---|---|
| At or over the user's bar | `{ passed: true, reasons: [] }` | the match |
| Under the bar | `{ passed: false, reasons: ["Scored 60, under your fit bar of 75"] }` | `null` |
| Gate failed | `{ passed: false, reasons: [<gate reasons>] }` | `null` |
| Scorer could not run (no confirmed fact, cap reached, paused, model down) | `{ passed: true, reasons: [] }` | the match; unscored, so out of the feed until it is scored |
| No preferences | `{ passed: true, reasons: ["Add your preferences to check fit"] }` | the match |

The web's existing "below the bar" view shows these reasons and lets the user go on, so it needs no change.

- `matchId` is `null` more often than before. Neither import component reads it.
- `GET /api/jobs/:jobId/fit` still returns the `matchId` of a below-bar match, so **Create draft** still queues it. The server marks that application `gate_override` when the gate had failed.
- A scored import at or over the bar now appears in the feed. An unscored one still does not.
- A second import of a scored posting makes no model call and reports from the stored match. A second import of an unscored one scores it now, and the result can differ from the first answer: it can reach the feed, or come back under the bar. A backfill or a fan-out can also score it later, with no request from the web.

## 4. One new error on import

`503 service_unavailable` with `details: { reason: "board_unavailable" }` means the board refused or failed the request. The unit is refunded, and the message is safe to show. The existing `err.message` fallback in `job-url-import.tsx` already displays it.

## 5. `GET /api/admin/board-requests` returns text a user pasted

`host` and `path` come from links users typed. Render them as escaped text, and **never build an `href` from them**: an admin link to a user's URL is a way to get the owner to open it. No screen uses this route yet.
