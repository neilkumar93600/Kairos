# WP-06 frontend handoff

WP-06 meters the four AI routes per day, maps model failures to proper statuses, and moves the tailor route to a cheaper model. No success response changes shape. Nothing in web/ was edited by this package. Item 1 matters from the first deploy; items 2 and 3 matter once the owner turns the gateway on (`LLM_GATEWAY=anthropic`).

## 1. 429 daily_allowance on the four AI routes (new)

| Route | Feature | Units |
|---|---|---|
| `POST /api/resume/suggestions` | `resumeSuggestions` | 1, or 4 for `scope: "resume"` |
| `POST /api/jobs/:jobId/tailor` | `jobTailor` | 1 (0 when the user has no confirmed fact) |
| `POST /api/applications/:id/drafts` | `applicationDrafts` | 1 |
| `POST /api/jobs/import` | `jobImports` | 1 |

Daily limits come from `aiDailyAllowance` in `shared/src/plans.ts` (Free: 10, 5, 10, 3). When the day's units are spent:

```json
429 { "error": { "code": "rate_limited", "message": "You have used today's AI allowance for this. It resets at 00:00 UTC.",
  "details": { "reason": "daily_allowance", "feature": "resumeSuggestions", "limit": 10, "used": 10, "resetsAt": "2026-11-04T00:00:00Z" } } }
```

A request that fails before the model answered (validation, 404, `invalid_scope`, `unsupported_board`, a provider outage) gives its units back. One whose answer was then refused (`422 truth_lock`, `422 ai_refused`) does not.

The same `429 rate_limited` code already comes from the per-minute limiters ("Too many AI requests. Try again in a minute."), which have no `details`. Branch on `details.reason`:

- `web/components/resume/bits.tsx:139` `askErrorText` says "Try again in a minute" for every 429. For `details.reason === "daily_allowance"` show the reset time instead, for example "You have used today's AI suggestions. They reset at {local time of resetsAt}." (05-api open item 11). Keep it calm (the `InlineError` calm style is right) and do not offer a retry button.
- `web/components/dashboard/queue/draft-assist.tsx:162` says "That was a lot of drafts in a minute". Same branch: "You have used today's AI drafts. They reset at {time}. You can still write the answer yourself."
- `web/components/dashboard/matches/job-url-import.tsx:36-37` handles `unsupported_board` and `posting_not_found` only; a 429 falls to the generic error. Add: "You have imported {limit} jobs today. Imports reset at {time}."
- `402` still means "no credits" and never means an AI limit.

A plan with 0 of a feature answers `403 forbidden` ("This AI feature is not on your plan"). None of the four routes above has 0 on any plan today.

## 3. Model failures are no longer 500 (new codes, gateway on)

| Status | `code` | When | Suggested UI |
|---|---|---|---|
| 503 | `ai_unavailable` | Anthropic busy or down after retries, the breaker open, a timeout, a missing key | Show the server message ("The writing assistant is busy. Try again in a minute.") with a retry |
| 422 | `ai_refused` | The model declined this one | Show the server message ("The assistant could not write this one. Try a different line or add a fact."); no automatic retry |
| 429 | `rate_limited`, `details.reason: "daily_allowance"`, `details.resetsAt` | The user's own daily AI spend cap (a backstop behind item 1); `feature`, `limit` and `used` are absent here | Same copy as item 1 |
| 429 | `rate_limited`, `details.reason: "service_budget"` | Kairos shed AI work to stay within its own daily budget | "AI suggestions are paused for now. Try again later." No reset time is promised |

`web/lib/api.ts` already turns any non-2xx into `ApiError` with the server `message`, so nothing breaks without changes; today these cases show "Something went wrong on our side". The legacy client (before the gateway is on) also answers `503 ai_unavailable` now instead of `500`.

## 4. Tailor suggestions now come from the tailoring model (behaviour, no shape change)

`POST /api/jobs/:jobId/tailor` returns the same `{ resume, suggestions, fit }`. Suggestions are now only `rewrite` (of a line that cites the same fact) and `add` (into the section the line belongs to); there are no `remove` and no `needsFact` suggestions on this route, and `why` reads "Tailored toward {job title}". A user with no confirmed facts gets an empty `suggestions` list. `web/components/resume/workspace.tsx` and `editor.tsx` already handle these actions.

## 5. Questions about personal details are never drafted (widened)

`422 profile_only` on `POST /api/applications/:id/drafts` now also covers date of birth, age, nationality, marital status, religion, caste, passport, SSN, national id, Aadhaar, PAN and driver's license questions. `draft-assist.tsx` already handles `profile_only`; optionally hide "Draft with AI" for those labels too.
