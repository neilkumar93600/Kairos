# WP-50 frontend handoff: newsletter sign-ups

Additive; nothing the web already calls changes. Schemas in `shared/src/schemas.ts` (`newsletterSignupSchema`, `NEWSLETTER_SOURCES`, `NewsletterSignup`). The web calls the api same-origin through its `/api` rewrite, like `/api/contact`.

- `POST /api/newsletter` with `{ email, source, website? }`, no session. `source` is one of `popup`, `blog-index`, `blog-post`, `about`. The api trims and lower-cases `email` (at most 254 characters).
  - `202 { ok: true }` for every valid body: a new address, one waiting for confirmation and one already subscribed all get the same answer. So the success copy is "Check your inbox to confirm", never "You're subscribed".
  - `422 invalid_body` (not 400: the api's validation convention since WP-30, `error.details` holds zod issues) for a bad address or source. Show "Enter a valid email address".
  - `429 rate_limited` with `details.bucket: "newsletter"` after 5 sign-ups an hour from one IP; `retry-after` is set. Show "Too many tries, please try again later".
- `website` is the honeypot. Render it as a real text input named `website`, visually hidden (off-screen, not `display:none`), `tabindex="-1"`, `autocomplete="off"`, `aria-hidden="true"` on its wrapper, and send whatever it holds. A filled value gets the same 202 and nothing is stored, so never pre-fill it and never tell the user.
- No GET changes anything, because mail scanners open every link. Emailed links open a web page, and only that page's button acts.
- Confirm: the email links to `${WEB_ORIGIN}/newsletter/confirm#token=<token>`. The button sends `POST /api/newsletter/confirm?token=<token>`, no body: `200 { ok: true }`, or `404 not_found` for an unknown, used or expired token. A token works once, for 7 days, so a second click is a 404. Suggested 404 copy: "This link has expired or was already used. If you already confirmed, you're subscribed; otherwise sign up again."
- Unsubscribe: the email's body links to `${WEB_ORIGIN}/newsletter/unsubscribe#token=<token>`. The button sends `POST /api/newsletter/unsubscribe?token=<token>`, no body: `200 { ok: true }`, or `404 not_found` for an unknown token. Repeating it is a 200. A row is deleted 30 days after its unsubscribe, so a very old link can get the 404. Mail clients POST the same path directly (RFC 8058 one-click, from the `List-Unsubscribe` header).
- `GET /api/newsletter/unsubscribe?token=<token>` is only for clients that open the header URL. It changes and reads nothing, and answers 303 to `${WEB_ORIGIN}/newsletter/unsubscribe#token=<token>`, or to `${WEB_ORIGIN}/newsletter?status=invalid` when the token is not of our shape. `GET /api/newsletter/confirm` does not exist (404).
- Both pages read the token from `location.hash` on the client, clear it with `history.replaceState`, and set `referrer: "no-referrer"`. No token in the hash is the invalid state. Both POSTs use the `link` limit class: `429 rate_limited` with `details.bucket: "link"` after 20 a minute from one IP.
- `/newsletter` (FE-pages) reads only `status`; the api sends only `invalid` to it now.
- Never put the address in analytics events, URLs or logs. Fire a `newsletter_signup` event with `source` only, on the 202.
- Sign-ups for one address send at most one confirm email per 10 minutes. A person who asks again within that time gets the 202 and no new email; the copy can say "If it doesn't arrive in a few minutes, check spam".

## The issue sender (not built)

Nothing sends newsletter issues yet, so nothing breaks today. There will be two lists: WP-35 (branch `wp/35`, in progress) builds account-level opt-out with `mail_opt_out`, so an account holder can opt out and still be a confirmed newsletter subscriber. Whoever builds the newsletter send must go through the WP-44 notify core and check `email_suppressions` and `mail_opt_out` as well as subscriber status. For the web, this means email preferences and the newsletter unsubscribe page are separate controls until then: do not tell a person that one also changes the other. Rules for the sender: owner-actions/WP-50.md section 3.
