# WP-04 frontend handoff

No route changes shape. Two web edits follow, plus two notes. Nothing in `web/` was edited by this package.

## 1. Receipt view: an unconfirmed cloud send is not "Not sent" (required before the cloud channel opens)

File: `web/components/dashboard/applications/receipt-view.tsx`, the `failed` state (around line 82). The cloud applier now stores one sentence from a fixed catalog in `failureReason`, never exception text. One of them marks the needs_check outcome. The applier pressed submit, the employer's page never confirmed it, and the employer may have received the application. On Greenhouse and Lever that is the usual result until spike S-AP2 lands, because their confirmation is a new page load. The current title "Not sent" and body "The application did not go through." are wrong for it. A user who believes them sends the application twice.

Until WP-29 adds a `failureCode` field, detect it by the sentence's fixed start:

```ts
const unconfirmed = application.failureReason?.startsWith("We could not confirm") ?? false;
// ...
failed: {
  title: unconfirmed ? "Not confirmed" : "Not sent",
  body: unconfirmed
    ? "The cloud applier pressed submit, but the employer's page did not confirm it. Check your email for their confirmation before you send it again."
    : "The application did not go through.",
  rows: [
    ["Reason", reason],
    ["Credit", "None charged. Failed applications cost nothing."],
  ],
},
```

The list row (`applications-table.tsx:128`) already prints `failureReason` under the status, so it needs no change.

## 2. Approve 403: offer "Upgrade your plan" only for the plan message

File: `web/components/dashboard/queue/send-controls.tsx`, `ApproveError` (the 403 branch). `POST /api/applications/approve` with `channel: "cloud"` answers `403 forbidden` with one of two messages:

- `"The cloud applier is not open yet"`: the channel is still owner-only (`CLOUD_APPLIER_OPEN=0`). Pro and Max users see this today. "Upgrade your plan" does not help them, so show the message alone.
- `"The cloud applier is on Pro and Max"`: the channel is open and the plan lacks it. Keep the upgrade link.

```ts
if (e?.status === 403 && e.code === "forbidden") {
  const upgrade = e.message.includes("Pro and Max");
  return (
    <p role="alert" className="text-sm text-bad">
      Not approved. {e.message}.{upgrade ? <>{" "}<Link href="/billing" className={inlineLink}>Upgrade your plan</Link></> : null}
    </p>
  );
}
```

`GET /api/me` does not say whether the channel is open. Keep the Cloud option driven by `plan.cloudApplier`, and let this message explain the 403.

## 3. Failure reasons the cloud applier stores (no change needed)

Show them as they are. They come from `FAILURE_MESSAGES` in `server/src/services/submissions.ts`:

| Code (server only for now) | `failureReason` |
|---|---|
| `challenge` | The employer's site asked for a human check, so the cloud applier stopped. Nothing was sent and no credit was used. You can send it from the extension. |
| `posting_closed` | This posting has closed. Nothing was sent and no credit was used. |
| `required_missing` | A required question had no answer, so nothing was sent and no credit was used. Fill it in, then resend. |
| `applier_error` | The cloud applier stopped before the submit step. Nothing was sent and no credit was used. You can resend it. |
| `plan_lapsed` | Your plan no longer includes the cloud applier. Nothing was sent and no credit was used. You can send it from the extension. |
| `unconfirmed` | We could not confirm whether the employer received this application. No credit was used. Check your email for the employer's confirmation before you resend. |

Extension failures still carry the extension's own text.

## 4. Extension report (no web change)

`POST /api/extension/report` with `outcome: "failed"` for an application the cloud applier is sending (`channel: "cloud"`, `status: "submitting"`) now answers `409 conflict` "Application is being sent by the cloud applier". The frozen extension ignores the response. `submittedAt` is now the server's time for both channels.
