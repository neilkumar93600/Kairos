# WP-44 frontend handoff: notifications

Additive; nothing the frozen web calls changes. Schemas in `shared/src/schemas.ts` (`notificationSchema`, `notificationsQuerySchema`, `notificationsResponseSchema`, `notificationsReadSchema`).

- `GET /api/me` gains `unreadNotifications: number` (the bell badge).
- `GET /api/notifications?limit=50&cursor=&unread=true` (session) answers `{ notifications, unread, nextCursor? }`, newest first, `limit` 1 to 200. Each item: `{ id, kind, createdAt, readAt, title, applicationId, detail }`. `kind` is one of `autopilot_sent`, `autopilot_paused`, `resend_available`, `offer_pause_notice`, `reply_important`, `forwarding_code`. `title` is plain text (escape it). `applicationId` links to the application page when set. `detail` holds codes only (e.g. `failureCode`). Pass `nextCursor` back as `cursor` unchanged; a bad cursor is 400 `invalid_param`.
- `POST /api/notifications/read` with `{ ids: uuid[] }` (1 to 100) or `{ all: true }` answers `{ updated }`. Idempotent.
- Poll at most every 120 s while the tab is visible (05-api capacity table).
- Signed-link pages (resend, unsubscribe, offer-pause undo) are server-rendered HTML on the api origin; the web has nothing to build for them.
