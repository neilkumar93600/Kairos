# WP-14 frontend handoff: the file download route

One new route, `GET /api/files/<key>`. No existing route changes, and no web change is needed yet: nothing returns a storage key until WP-17 (imported resume files) and WP-29 (the sent snapshot on the receipt). Nothing in `web/` was edited by this package.

## 1. `GET /api/files/<key>`

A storage key looks like `snapshots/<userId>/<sha256>.pdf` or `uploads/<userId>/<id>.docx`. It has three segments, and only `[A-Za-z0-9._-]` within them. The web gets keys from other API responses (for example a future `resumeFileKey` on an application). It never builds one.

Call it through the `/api` rewrite like any other route, so the session cookie goes with it:

```tsx
<a href={`/api/files/${key}`} download>Download the PDF that was sent</a>
```

Put the key into the path as it is. Do not `encodeURIComponent` it: an encoded `/` (`%2F`) makes the key unreadable and the route answers 404. The key needs no escaping.

| Status | Body | When |
|---|---|---|
| 200 | The file bytes, `Content-Disposition: attachment; filename="<name>"`, `Cache-Control: no-store` | The key is the signed-in user's and the object exists |
| 401 | `unauthorized` | Signed out |
| 404 | `{ "error": { "code": "not_found", "message": "File not found", "requestId": "..." } }` | Missing, another user's key, a malformed key: always the same body |
| 429 | `rate_limited`, `details.reason = "user_limit"` | The per-user limit (600 a minute, shared with every signed-in route) |
| 503 | `storage_unavailable` | Storage is not configured on that api. Expected on local `next dev` against an api without R2 |

Content types are `application/pdf`, the DOCX type, `text/plain`, or `application/octet-stream` for anything else.

## 2. Previews

Every file is sent as an attachment, with `Content-Security-Policy: default-src 'none'; sandbox`, so the browser downloads it rather than showing it. That is deliberate: an uploaded file must never render on our origin. To show a PDF inline (for example a receipt preview), fetch it and display a blob URL:

```ts
import { ApiError } from "@/lib/api";

const res = await fetch(`/api/files/${key}`, { credentials: "include" });
if (!res.ok) {
  // `api()` in lib/api.ts parses JSON bodies, so a file needs its own fetch; errors use the same envelope.
  const body = (await res.json().catch(() => null)) as { error?: { code: string; message: string } } | null;
  throw new ApiError(res.status, body?.error?.code ?? "unknown", body?.error?.message ?? "Request failed");
}
const url = URL.createObjectURL(await res.blob());
// <iframe src={url} title="Sent resume" /> and URL.revokeObjectURL(url) on unmount
```

Show only PDFs this way, never uploads of other types.
