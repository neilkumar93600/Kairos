# WP-16 frontend handoff: build R1 to R4 against the QA mock

The contract is final enough to build on (decision D7: web first). Nothing in `web/` was changed by this package.

## What to import

- Types and zod: `@auto-career/shared` (`shared/src/schemas-suite.ts`, enums in `types.ts`). `RESUME_SUITE_ROUTES` lists every route with its method, path, request, query and response schema and the error codes to handle.
- The mock: `web/scripts/qa/mock-api.mjs` (`fixtures("full" | "empty")`, `handleApi` for Playwright). The suite routes live in `mock-suite.mjs`. `shots.mjs` and `check-schemas.mjs` are copied into this branch (they were untracked in the main checkout).
- Shots: `node web/scripts/qa/shots.mjs --routes /resumes,/tracker` already treats `/resumes`, `/tracker`, `/contacts`, `/interviews` as signed-in routes.
- The fixtures are stateful inside one `fixtures()` object: create, confirm, drag and delete change what the next GET returns. Each call returns a fresh copy.

## Routes (all under `/api`)

PRD section 11 as written, plus three additions: `PATCH /resumes/:id` (rename, target roles), `GET /resumes/:id/revisions/:revId` (the revision's document, for Compare), `GET /tracker/:id` (job detail page for `/tracker/[itemId]`: private notes, posting text, contact ids). `POST /resumes/suggestions` now requires `resumeId`. `GET/PUT /resume`, `POST /resume/suggestions` and `POST /jobs/:jobId/tailor` are untouched aliases.

## Things the screens must handle

1. **Spent daily AI allowance is `429`, not `402`.** Body: `error.code = "rate_limited"`, `error.details = { reason: "daily_allowance", feature, limit, used, resetsAt }`. Show the reset time (00:00 UTC), not "try again in a minute". `402` stays "no credits". Successful metered calls carry `Kairos-Allowance: feature=...;used=...;limit=...;resets=...`. A plan with 0 of a feature answers `403 forbidden`.
2. **Truth lock.** `PUT /resumes/:id` answers `422 truth_lock` with `details.lineIds` (`"headline"` for the headline). Imported facts are unconfirmed until the user confirms them; a line cannot be saved until its fact is confirmed. Suggestions with `needsFact` have no text to accept, only a question.
3. **Sent resumes are read-only.** `resume.readOnly` true: every write answers `409 read_only`. Offer "Duplicate as a new base resume" (`POST /resumes { from: "duplicate", sourceId }`) and "Tailor again".
4. **Library name vs person name.** The detail has `libraryName` ("Frontend") and the document `name` (the person). The summary, `POST /resumes` and `PATCH /resumes/:id` use `name` for the library name.
5. **Limits.** `409 limit_reached` at 10 base resumes per profile; `409 is_default`, `409 last_base` on delete; `409 exists` on tailor carries `details.resumeId` (open that resume instead).
6. **Export.** `GET /resumes/:id/export?format=pdf|docx|txt` returns a file; `503 service_unavailable` means fall back to browser print with the notice. Mock only: add `&simulate=503` to see it. The file name comes from `Content-Disposition`.
7. **Import.** `POST /profile/imports` (multipart `file`, or JSON `{ text }`) answers `202`; poll `GET /profile/imports/:id`. The mock shows `pending` ("Reading your resume"), `parsing` ("Finding your roles"), then `parsed` on the third read. Mock only: a file name containing `scan` gives `422 no_text_layer`, `huge` gives `413`, an extension other than pdf or docx gives `415`. `duplicates` lists fact ids already in the profile (show "Already in your profile"); `contact` is offered for Profile, not stored as a fact. Build with `POST /resumes { from: "facts", importId, name }`: only confirmed facts become lines.
8. **Tracker.** Stages `saved, drafting, applied, interviewing, offer, closed`; Closed needs `closedReason`. `409 stage_owned_by_pipeline` has `details.reason` (`approve_in_review_queue`, `withdraw_first`, `pipeline_stage`) and a ready-to-show `message`. Positions are opaque ascending strings. Every drag also needs the keyboard "Move to..." path (same PATCH). Mock only: `POST /__mock/pipeline { itemId, event }` with `drafted | submitted | failed | withdrawn | reply_interview | reply_offer | reply_rejection` plays the automatic moves so you can see Applied, Interviewing and the "Send failed, credit refunded" badge (`sendFailedRefunded`).
9. **Insights** are Pro and Max (`403 forbidden`, message names the plan). `lowSample` true means show counts only; rates are `null` below 5 sent, per group too. In the mock the `empty` scenario is Free, `full` is Pro; `range=30d` has the low-sample case.
10. **Private text.** `notes`, `salaryText` and contact `notes` are never in the list rows or the timeline payloads; "note added" has no text.
11. **Interviews** need `startsAt` and `timeZone`; there is no guessing. `GET /tracker/:id/interviews/:iid.ics` is the calendar download.

## Plan fields

`GET /me` plan objects now also carry `dailyScoringCap`, `matchCadenceMinutes`, `autopilotDailySendCap` and the spec `dailyModelSpendCapUsd` (0.05, 0.20, 0.25, 0.50). The UI should not show the cost fields; `autopilotDailySendCap > 0` is the Autopilot plan gate (later package).

## Not in the contract yet (needs a decision before the receipt screen)

The application detail response has no field for the sent resume snapshot and template name (PRD 6.1, 7.6 "the receipt names the version and template"). Use `GET /resumes/:id` for the tailored copy (`resume.applicationId`) until a later server package adds it to `GET /applications/:id`.
