# WP-35 frontend handoff: email preferences, saved searches, unsubscribe

Additive; nothing the frozen web calls changes. Schemas are in `shared/src/schemas.ts`.

## Email preferences (Settings > Notifications)

- `GET /api/email-preferences` (session) answers `{ emailPreferences: { digest, outcomeReport, autopilotSummary, reminders } }`; `true` means "send me this".
- `PATCH /api/email-preferences` with any non-empty subset of those four booleans answers the same object. 422 `invalid_body` for an empty body or an unknown field.
- **New accounts start with all four `false`** (consent is required; `MAIL_CONSENT_DEFAULT` can change that, so read the values, do not assume). Turning one on records the person's consent; turning it off withdraws it. The change applies to the very next email, including one already queued.
- A switch can read "on" while a spam-complaint suppression still stops optional mail to that address (`email_suppressions`, set by Postmark); the preferences do not show it. If the person says they get nothing, that is the first thing support checks.
- Account mail (sign-in codes, receipts, resend links, billing notices) cannot be turned off and is not in this object. Say so in the UI.

## Saved searches (digests)

- `GET /api/saved-searches` -> `{ searches }`, at most 10, oldest first. Each: `{ id, name, filters, frequency, nextDigestAt, createdAt }`. `frequency` is `off`, `daily` or `weekly` (weekly = Monday), sent at 08:00 in the person's time zone (`PUT /api/profile/contact` takes `timezone`). `nextDigestAt` is null while off.
- `POST /api/saved-searches` `{ name (1-60), filters?, frequency? }` -> 201 `{ search }`. `filters` is `{ minScore?: 0-100, roles?: string[<=10], companies?: string[<=20], remoteOnly?: boolean }` and adds no scoring. 409 `exists` for a name already used (case-insensitive), 409 `limit_reached` `{ limit: 10 }` at the eleventh. (05-api 10.8 says 422 for the limit; the code catalog has `limit_reached` as 409, as WP-17 uses it.)
- `PATCH /api/saved-searches/:id` merges any of `name`, `filters`, `frequency` -> `{ search }`; 404 for a missing or foreign id. `DELETE` is 204 whether or not it existed.
- Every account gets one search named "My matches" (daily) at sign-up. **A new search sends nothing until the digest switch above is on**; say so next to the frequency control (a search set to daily with the switch off is silent).

## Unsubscribe pages

`/api/unsubscribe?t=...` is an HTML page on the api origin (like the resend page): GET shows what will stop, the button POSTs. Nothing to build. The link is reusable: a second click, a refresh and Gmail's one-click button all end on "You are unsubscribed". An unsubscribe done in Gmail's own button (Postmark event) also turns all four switches off.

## Contact form

`POST /api/contact` is unchanged for the client (202 `{ ok: true }`, 429 when rate limited). The same message sent twice the same UTC day is stored once and still answers 202.

## Notes for the packages that build on this

- **Autopilot (WP-36) and the weekly report:** register a renderer in `RENDERERS` (`jobs/notify.ts`) for `autopilot_hourly` or `outcome_report`. They are already broadcast kinds: the notify job refuses them to an opted-out user, adds the unsubscribe headers and footer, and sends them on the broadcast stream, so a renderer returns only the content. Make the producer's selection filter on `profiles.mail_opt_out` too, so opted-out users are not claimed for nothing.
- **WP-24, WP-29, WP-33:** `forwarding_code`, `resend_available`, `return_to_draft`, `offer_pause_*` and `autopilot_paused` are transactional: no opt-out, no footer.
