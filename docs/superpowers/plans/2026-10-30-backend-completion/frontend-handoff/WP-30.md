# WP-30 frontend handoff: API hygiene and contract

No file in `web/` was edited. Four changes are visible to the web; only the first needs web work.

## 1. `403 reauth_required` on approve and billing (needs web work)

`POST /api/applications/approve`, `POST /api/billing/checkout` and `POST /api/billing/portal` now need a session created in the last 24 hours. An older session gets:

```json
{ "error": { "code": "reauth_required", "message": "Sign in again to continue", "details": { "maxAgeSec": 86400 }, "requestId": "..." } }
```

Sessions last 30 days, so a user who signed in last week will hit this on their first approve or checkout. Today the web shows `message` for any non-2xx, so the user sees "Sign in again to continue" with no way to act on it. Wanted: on `ApiError.code === "reauth_required"`, show a "Sign in again" button that signs out and goes to `/sign-in?next=<current path>`, and keep the pending action (selected ids, plan) so the user can repeat it after signing in. The extension is unaffected (it does not call these routes). `GET /api/billing/*` does not exist, so no read is affected.

## 2. Lists accept `limit` and `cursor`, and may return `nextCursor` (additive)

`GET /api/matches`, `GET /api/applications` and `GET /api/inbox` take optional `?limit=1..200&cursor=<opaque>`. With neither, the answer is the same first page as before (100, 200 and 100 rows). When more rows exist the body gains `nextCursor`; pass it back as `cursor` for the next page. A bad `limit` or `cursor` is `400 invalid_param`. A cursor from one list is refused by another. The web ignores the new field today, so it still shows only the first page; "load more" can use it later.

`GET /api/applications` rows gain `updatedAt` (ISO string). Nothing else in a row changes.

## 3. New response headers and CORS

Every `/api` response carries `Kairos-Contract: 2026-10-23`. Cross-origin requests may send `X-Kairos-Client`, `Idempotency-Key`, `If-Match` and `If-None-Match`, and browsers can read `Retry-After`, `RateLimit`, `Kairos-Allowance` and `Kairos-Contract`. The web is same-origin through the rewrite, so nothing changes for it.

## 4. New error: `503 timeout`

A route that exceeds its server deadline (10 s default, 15 s for `PATCH /api/applications/:id`, 30 s for `GET /api/jobs/:jobId/fit`, 60 s for the model-backed routes) answers `503 timeout` with `Retry-After: 5`. The web treats any non-2xx as an error and shows `message` ("This took too long. Try again."), which is enough.

Also: the model-backed routes (`/resume/suggestions`, `/jobs/:id/tailor`, `/applications/:id/drafts`) now share one 10-a-minute `ai_burst` count per user across all api replicas, so a 429 `rate_limited` with `details.bucket = "ai_burst"` can arrive slightly earlier than before when the api runs on several instances. The status and code are unchanged.
