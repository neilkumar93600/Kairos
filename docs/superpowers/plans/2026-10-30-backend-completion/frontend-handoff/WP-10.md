# WP-10 frontend handoff

No frozen route changes shape on success. Two billing routes gain error answers, `GET /api/me` reports the effective plan, and the 402 on approve gains details. Nothing in web/ was edited by this package. Item 1 is required in the same release as the server change; the others are small follow-ups.

## 1. Checkout: 409 `already_subscribed` sends the user to the portal (required)

`POST /api/billing/checkout` now refuses a second subscription. When the user's Stripe customer already has a live subscription (active, trialing, past_due, unpaid or paused), it answers:

```json
409 { "error": { "code": "already_subscribed", "message": "You already have a plan. Change it in the billing portal", "details": { "portalUrl": "https://billing.stripe.com/p/session/..." } } }
```

Redirect to `details.portalUrl`; the user changes plan or fixes the card there. File: `web/hooks/use-billing.ts`.

```ts
import { ApiError, post } from "@/lib/api";

checkout: useMutation({
  mutationFn: (input: { plan: Exclude<PlanId, "free">; interval: BillingInterval }) => post<{ url: string }>("/billing/checkout", input),
  onSuccess: ({ url }) => window.location.assign(url),
  onError: (e) => {
    const portalUrl = e instanceof ApiError && e.code === "already_subscribed" ? (e.details as { portalUrl?: string } | undefined)?.portalUrl : undefined;
    if (portalUrl) window.location.assign(portalUrl);
  },
}),
```

The common way to hit this is item 2: a user more than 7 days past due sees plan Free and the upgrade buttons.

## 2. Past due: `plan` is the effective plan, `subscription.status` is Stripe's

A failed renewal keeps the paid plan for 7 days, then `GET /api/me` returns the Free plan in `plan` while `subscription.status` stays `past_due` (and `subscription.plan` still names the paid plan). `plan-summary.tsx` decides `paid = plan.id !== "free"`, so such a user sees the checkout buttons instead of "Change, pause or cancel".

Suggested change in `web/components/dashboard/billing/plan-summary.tsx`:

```ts
const needsPortal = ["past_due", "unpaid", "paused"].includes(subscription?.status ?? "");
const paid = plan.id !== "free" || needsPortal;
```

and, when `needsPortal`, label the portal button "Fix payment". The existing status word "Payment past due" already covers the status row.

`subscription` is still the raw row (WP-05 replaces it with a pick-list), so it now also carries `pastDueSince` (ISO time or null). If you want to say "Your paid features pause on <date>", that date is `pastDueSince + 7 days`; ask WP-05 to keep the field in its pick-list before relying on it.

## 3. Stripe outages are 503 `billing_unavailable`, not 500

Checkout and portal now answer `503 { error: { code: "billing_unavailable", message: "Billing is unavailable right now. Try again in a minute." } }` when Stripe fails or times out (10 seconds). `ErrorNote` already shows the message; no change needed unless you want a retry button.

## 4. 402 on approve carries the numbers (optional)

`POST /api/applications/approve` with too few credits still answers 402 `payment_required` with the same message, and now `details: { available: number, requested: number }`. `ApproveError` in `send-controls.tsx` can use them, for example "You have 3 credits for 5 applications". No change is required.
