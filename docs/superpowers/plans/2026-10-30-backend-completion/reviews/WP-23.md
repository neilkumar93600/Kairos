## Where the build departs from the plan or the spec, for the reviewers to challenge

| # | Departure | Why |
|---|---|---|
| 1 | `safeFetchJson` uses `node:https`, not undici (the 06-infrastructure 7.4 sketch). | undici is a dev dependency only. The agent's `lookup` is the connect-time hook, and agent options win over request options when Node opens the socket. |
| 2 | One private answer in a resolved set refuses the whole name. All of `::ffff:0:0/96` is refused, public mapped addresses included. NAT64, 6to4 and Teredo are refused too. | Stricter than the spec sketch; a public board answers with none of these. Mapped addresses are in their own `BlockList`, because a BlockList applies an IPv6 rule to IPv4 addresses in mapped form, which would have refused every IPv4. |
| 3 | Host back-off lives in Redis with a TTL, not an `ops_flags` row (01-ingest-poller 3.4). | `ops_flags_key_ck` and setFlag's audit trail are for operator switches, and a key that expires cannot get stuck on. Cost: the owner cannot see or clear a rest in `/api/admin/flags`. |
| 4 | The prefilter runs per job over users, against the `preferences` jsonb. Role and location matching lower-cases ASCII with `translate()`, and any value with a non-ASCII character counts as matching. | The coordinator asked for a per-job query with paged users; 04-matching 6.2 sketches per user over jobs, which `jobsForUser` (the backfill) follows. `lower()` depends on the collation, so SQL stays loose there and the TypeScript gate decides. |
| 5 | A pasted posting missing from a trusted listing closes only after its own endpoint says it is gone (`closed_by = posting_fetch`, 20 checks a poll). Ashby's listing is taken as the answer. | Greenhouse and Lever can serve postings their boards do not list. This stands in for `recheckImportedJobs` and `jobs.next_check_at` (01-ingest-poller 3.8). |
| 6 | Imported company due check misses `companies_due_idx`. | Marked `ponytail:`. Fine at a few thousand companies. |
| 7 | `next_poll_at` is scheduled from now, not fixed-rate from `dueAt`. No per-board 1 req/s limiter and no Ashby floor beyond the cadence. Concurrency is `maxSockets: 4` per host, per process. | Interim. The cadence never drops below Ashby's 60 s. |
| 8 | Unscored `new` imports stay (0011's comment expected them moved to `expired`). | The route still writes them when the scorer cannot run, and the feed shows only scored matches. M-4 therefore checks pipeline rows only. |
| 9 | Imported jobs are never updated or reopened by a close-only poll. | "Never inserts, never scores"; the smallest reading of close-only. |
| 10 | Exploration slot, half credit for unconfirmed facts, `cold_start_daily_cap` and the synchronous first 15 backfill pairs are not built. | Not in the WP text. They come with WP-34's pacing. |
| 11 | M-1 and M-2 are not built; M-3 is a check on overdue close-only polls; M-4 is a nightly check. | M-1 needs `user_match_state` and M-2 needs ghost verdicts, both WP-34. `next_check_at` does not exist, so M-3 reads `companies.next_poll_at`. |
