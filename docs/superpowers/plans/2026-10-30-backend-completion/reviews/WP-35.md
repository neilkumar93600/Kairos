## Decisions the builder made that reviewers should check

1. **The opt-out store is `profiles.mail_opt_out`** (spec, already registered) plus a new `mail_opt_outs` table keyed by `addressHash` that outlives the account (registry `keep`, like `email_suppressions`). Unsubscribe and a preference toggle write both; sign-up reads the second. Chosen over reusing `email_suppressions` because its reasons stop all mail (or all broadcast), not one kind. Keyed with the erasure normaliser (aliases of one address are one objection) and its own HMAC label, so it cannot be joined to the suppression list.
2. **Send-time enforcement** is in `processNotify` (`jobs/notify.ts`), for every kind in `BROADCAST_OPT_OUT` (`lib/broadcast.ts`): a refused user gets `suppressed/unsubscribed` (`no_recipient` without a profile) before the renderer runs; headers and footer are added there too, so no future broadcast renderer can forget them.
3. **Unsubscribe token** is per user, kind and UTC day (not per month as 05-api says) and reusable (item 2); the link action is `oneClick: true` and `reusable: true`, with its own 410 page text (`LinkAction.gone`).
4. **Consent default** `MAIL_CONSENT_DEFAULT=opt_out`; the DB default of `mail_opt_out` is now all four kinds; migration 0018 opts every existing profile out.
5. **Digest window**: `saved_searches.window_start` (not in the spec) keeps the window of the latest claim so a retry or redrive renders the same matches; an entity whose local date no longer matches the claim is `superseded`.
6. **Not built**: the `pause_email_broadcast` ops flag (messaging-57, WP-27's area), contact `status`/`handled_at` triage columns, `reminders.match_id`, digest jitter (the notify queue's priority already keeps broadcast behind transactional mail), `autopilot_hourly` and `outcome_report` renderers (WP-36 and the report package), `resend_available`, `return_to_draft` and `forwarding_code` renderers (WP-29, WP-24).
7. **Test harness note**: the integration tests were also run locally against PGlite (WASM Postgres 17-compatible) behind a socket; that found one real bug (raw `execute` returns timestamptz as text) before commit. `authz-matrix.int` could not run there (it needs a per-connection `kairos.actor` setting).
