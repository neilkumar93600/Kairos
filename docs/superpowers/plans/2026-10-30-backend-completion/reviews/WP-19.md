## Decisions the builder made that reviewers should check

1. **Who renders: the worker, always.** The api and the applier enqueue on `render` and wait. The applier image has no Typst and its bundle has no template. The api bundle holds the code but never calls it.
2. **How the bytes reach the applier: a 60-second presigned URL in the job's return value, read once and then removed from Redis, and fetched from Node over https.** The alternative was bytes through Redis, which puts every PDF in a noeviction store. Jobs carry ids only, so no resume text sits in Redis. The worker gives a link only to a request that names the attempt and the worker identity holding it (open, launched, marked by that identity). *Corrected in round 1 (K1):* what a compromised applier replica can reach is what it could already reach through `get_applier_payload`. With the holder's identity, which is a replica name and not a secret, it can claim the render of an attempt it can name, and the employer's page never sees the URL. Blind, with only an application id, it gets nothing. Redis has no ACL, so a replica can still read a result in the moment between the worker writing it and the holder removing it, for at most 60 s. The link dies 60 s after it is signed.
3. **The render sits after the mark and the prechecks, before the page.** A delivery that loses the mark asks for nothing. Since round 1 a failure does not end the run: the page decides (S1).
4. **The attach comes before the `filling` mark** (07-cloud-applier 3.2 item 8 has it after). A failed attach, or `resume_missing`, can then still say nothing was sent. An ATS that uploads on `change` receives a file but no application.
5. **`applier_needs_render`, a new definer function.** Without it every send asks the queue, and a legacy row, the chaos harness and every existing fixture would wait 90 s for nothing. It returns a boolean and reads no content. It needs the roles script before the applier deploys (`owner-actions/WP-19.md`).
6. **`record_attempt_result` takes `render_failed`.** 0027's allowlist refused it. Same body otherwise.
7. **Exports wait behind sends** (BullMQ priority), and an export older than 30 s is dropped.
8. **A text-layer mismatch on export is the 503, not the spec's 500**: the user can still print. `signal("render_text_mismatch")` is A-WS-6. A mismatch and an oversized document do not retry.
9. **Filename:** `{Name} - {role} - Resume.ext`, role from `targetRoles[0]`, ASCII after NFKD, each part at most 60. A name with nothing left becomes `Resume.pdf`.
10. **The extension's PDF is behind `EXTENSION_RESUME_PDF`, off.** A presigned URL needs a CORS rule the owner must add, and a refused fetch throws inside the frozen filler. With it on, an item with a document is held back (and not leased) until its file exists, and the poll asks for the render. A final render failure fails that item.
11. **The five other template ids print as Classic** until WP-39.
12. **Paper:** `pageSize`, else Letter, the frozen default.
13. **`resumePlainText` replaces `renderResumeText`** for the txt export and the round trip: name, headline, contact, sections. Since round 1 (C4), F1 reads `resumeScoringText` instead: the headline and the sections, without the name and contact. All read `printView`, as does the template.
14. **Headings print as one line, `heading | subheading | meta`.** Right-aligned dates would reorder the text layer. Hidden and empty parts do not print.
15. **`--input` is capped at 120 KB of JSON**, because Linux refuses one argument over 128 KiB. A larger document fails as `render_too_large`.
16. **The render-queue job has no custom id for a cloud send**, so a re-delivery that wins the mark never reads an old result. The extension's job id is `render-<id>-<attempt>`, which dedupes polls (BullMQ refuses `:` in ids, so not the spec's `render:<id>:<n>`).
17. **Skipped:** the failing-hash deny set of workers/05 (the per-user limiter bounds a reload loop; add it if the worker shows churn), the reconciler row for approved-without-a-file (nothing renders before the claim), and vendored fonts (below).

## Known limits

- **No CJK, Hangul, Devanagari or emoji.** The embedded fonts lack them, and the round trip catches it (V1). Since round 1, a cloud send to a page with a resume input fails `render_failed`/`render_mismatch` with its own copy and no charge, and the cloud refuses to resend it, pointing to the extension. A page with no resume input sends without a file. Export falls back to print. The fix is vendoring Noto with `--font-path`, about 100 MB of image.
- **Real documents are rare until two other packages land.** `resumes_user_uq` still allows one resume per user, so `ensureTailoredCopy` often has no copy and the snapshot's document is null: no PDF, and a required resume input fails `resume_missing`. It lifts with the contract migration (wp/17-contract). And the tailored lines stay on `resume_lines`, so a document that does exist is the copy without them, until WP-41.
- **No OS-level network block on the child.** Typst fetches only for a package import, the template has none, and user text cannot add one. A non-root container has no `unshare`.
- **The extension link stays off** (K3) until the 13.5 route exists. With the flag on, a deterministic render failure would also fail the extension item; that path waits for the route too.
