# WP-27 owner actions: ops flags, metrics and the minimal admin

The code is on branch `wp/27`. It adds four tables (`ops_flags`, `feature_flags`, `ops_audit`, `metrics_minute`, migration 0009), the `/api/admin` routes, an hourly and nightly invariant check that freezes approvals, and an alert evaluator. Nothing changes for users until you set a flag. The env switches (`PAUSE_SCORING`, `LLM_SHED_LEVEL`, `CLOUD_APPLIER_OPEN`, `OWNER_USER_IDS`) keep working.

## 1. Re-run the role grants before deploying

`psql "$ADMIN_URL" -v ... -f ops/provision-roles.sql` as in WP-12 step 3. It now grants the new tables. Skipping this is not safe: without the grant `kairos_applier` cannot read `ops_flags`, the applier logs `flags not loaded` and then ignores `pause_cloud_apply` and `extension_only`. After the deploy, set `pause_cloud_apply` once on staging and watch the applier park a run (log line `cloud apply parked by an ops flag`).

## 2. Set ADMIN_USER_IDS

On `sd1-api` (and `sd1-worker`, harmless), set `ADMIN_USER_IDS` to your own user id, comma-separated for more. Empty means nobody can reach `/api/admin`: the routes answer 404. Use it by signing in again (the admin routes need a sign-in under 15 minutes old), then calling the routes with your session. There is no admin page yet; the routes and the flag names are in `docs/runbook/incident.md`.

## 3. Activate imported boards

Imported companies stay inactive until you activate them: `GET /api/admin/companies?active=false`, then `POST /api/admin/companies/<id>/activate`. Each call writes an `ops_audit` row.

## 4. Sentry alert rules for the new signals

In Sentry, add issue alerts that page you on messages titled `signal: invariant_breach`, `signal: slo_burn_fast`, `signal: llm_envelope_100`, `signal: cross_tenant_row`; and notify (no page) on `slo_burn_slow`, `slo_budget_half`, `llm_envelope_80`, `llm_escalation_cap`, `cost_per_submission`, `queue_lag`, `cloud_run_failures`, `pii_in_column`. The meaning of each is in the signals table of `docs/runbook/incident.md`.
