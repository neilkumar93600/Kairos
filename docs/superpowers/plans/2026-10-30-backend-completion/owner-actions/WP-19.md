# WP-19 owner actions: the resume renderer

Nothing here needs a decision. The steps are in deploy order, because the applier now depends on the worker and on the roles script.

## 1. Deploy order

The migrator adds `applier_needs_render` and lets `record_attempt_result` take `render_failed`. Then:

1. Set `pause_cloud_apply` (admin ops flags). Jobs stay approved and unclaimed.
2. Let the migrator run.
3. Re-run `ops/provision-roles.sql`, so `kairos_applier` can call `applier_needs_render`. Until this runs, every cloud send fails as `applier_error`, "nothing was sent", no charge, resendable.
4. Deploy the worker. It builds with Typst 0.15.1 in the image. Until it runs nothing consumes the `render` queue, and a send with a document fails as `render_failed` after 90 s: no charge, resendable.
5. Deploy the applier and the api.
6. Lift `pause_cloud_apply`.

## 2. R2

The buckets of `owner-actions/WP-14.md` must exist on the api and the worker. Without them a send with a document fails as `render_failed` (no charge, resendable), and export answers 503, which the web turns into the browser print. The api's `renders` token must be Read & Write and its `snapshots` token Read only, as WP-14 says.

## 3. Worker memory

Two Typst children at once, each capped at 256 MB. Add 512 MB to the worker's limit if it runs close to its limit today. The specs' 1.5 GB api limit (resume-52) does not apply: the api never renders.

## 4. Optional: the PDF for the Chrome extension

Off by default: the extension sends as it does today, with no file. The frozen filler fetches the link from the employer's page, and a fetch the bucket's CORS refuses throws there, so turn it on only in this order:

1. On the **snapshots** bucket only, add a CORS rule: method GET, no headers, origins `https://job-boards.greenhouse.io`, `https://boards.greenhouse.io`, `https://jobs.lever.co`, `https://jobs.eu.lever.co`, `https://jobs.ashbyhq.com`.
2. Set `EXTENSION_RESUME_PDF=1` on the api service.

Know this before turning it on: the link lives 5 minutes, and the frozen panel keeps its queue in memory. A send from a panel opened longer ago than that goes **without the file**, and the employer still gets the application. The fix is the 24-hour API-origin link of `05-api.md` 13.5; tell the team if you want it built before you turn this on.

## What you do not need to do

No new secret. The Typst binary is pinned by SHA-256 in `server/Dockerfile`, checked by the image build.
