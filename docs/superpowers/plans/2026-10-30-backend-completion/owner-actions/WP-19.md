# WP-19 owner actions: the resume renderer

Nothing here needs a decision. Follow the deploy order: the applier now depends on the worker and on the roles script.

## 1. Deploy order

All three services deploy together on a push, and the migration runs as the api service's pre-deploy (`node dist/migrate.js`, `.railway/railway.ts`). There is no separate migrator step to wait for.

1. Set `pause_cloud_apply` (admin ops flags). Jobs stay approved and unclaimed.
2. Push. The api's pre-deploy migrates: `applier_needs_render` is added, and `record_attempt_result` accepts `render_failed`. The worker and the applier deploy alongside it.
3. Once the api is up, so the migration has run, re-run `ops/provision-roles.sql`. It grants `kairos_applier` EXECUTE on `applier_needs_render`. **Run it after the migration, never before:** the script names that function, so before the migration it stops with error 42883 (function does not exist).
4. Lift `pause_cloud_apply`.

Without the pause, the deploy window fails sends cleanly but for nothing. A new applier against the old schema gets 42883 on `applier_needs_render` (`applier_error`, resendable). A new applier before step 3 gets 42501, with the same result. No charge either way.

## 2. R2

The buckets of `owner-actions/WP-14.md` must exist on the api and the worker. Without them, a send whose page has a resume input fails as `render_failed` (transient, no charge, resendable), and export answers 503, which the web will turn into the browser print. The api's `renders` token must be Read & Write and its `snapshots` token Read only, as WP-14 says.

## 3. Worker memory

Two Typst children at once, each capped at 256 MB. Add 512 MB to the worker's limit if it runs close to its limit today. The specs' 1.5 GB api limit (resume-52) does not apply: the api never renders.

## 4. The extension's PDF: leave it off

`EXTENSION_RESUME_PDF` stays unset (off) until the 24-hour API-origin link of `05-api.md` 13.5 exists. Turning it on puts a presigned storage URL into the employer's page. That link is a credential: any script running on those five ATS origins can replay it, and fetch that user's resume, for as long as it lives. With it off, the extension sends as it does today, with no file.

## What you do not need to do

No new secret. The Typst binary is pinned by SHA-256 in `server/Dockerfile`, checked by the image build.
