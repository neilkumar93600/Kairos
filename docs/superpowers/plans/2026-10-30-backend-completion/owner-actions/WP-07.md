# WP-07 owner actions: model provider terms and the privacy notice

The code is on branch `wp/07`. From this package on, resume text loses its contact header and personal-details lines (date of birth, visa and work authorization, salary or CTC, government ids, disability, veteran status, gender, ethnicity, age, nationality, marital status, religion) before the parser sees it, and the scorer's candidate summary loses contact details and the same lines. What still reaches Anthropic is resume and fact text about work: roles, employers, skills, results, education. These steps need your accounts and your sign-off. Do 1 and 2 before real users' resumes are parsed on production (CISO mustFix 6).

## 1. Confirm the Anthropic data processing terms

1. Sign in to the Anthropic Console with the organization that owns the production API key.
2. Find the commercial terms and the Data Processing Addendum that apply to the organization (the Console's legal or privacy settings, or Anthropic's trust and privacy pages linked from it). If you cannot find a DPA that covers your organization, ask Anthropic sales or support for it in writing.
3. Check three points and keep a copy (PDF or screenshot with the date) in your compliance folder:
   - Anthropic acts as a processor for API inputs and outputs, and does not train on them.
   - The default retention period for API inputs and outputs, and where the data is processed.
   - Sub-processors and how you are told about changes.
4. Reply "DPA confirmed" with the retention period you found, or tell me what is missing.

## 2. Request zero data retention (ZDR)

1. Ask Anthropic (sales or your account contact) to enable zero data retention for the production organization.
2. Ask them to confirm in writing which endpoints ZDR covers. Today the gateway uses only the Messages API with prompt caching (`server/src/llm/gateway.ts`); if batch scoring is turned on later, the Message Batches API matters too. Ask whether ZDR changes anything for those.
3. When it is on, note the date and the confirmation in the same folder and tell me. Until then, the privacy notice must not promise zero retention (step 3 keeps to what is true either way).

## 3. Name Anthropic in the privacy notice

File: `web/app/(legal)/privacy/page.tsx`, section "Who processes it" (line 19). The exact replacement text is in `frontend-handoff/WP-07.md`, item 3. Approve the wording (or edit it), then the web change ships with this package. Bump the page's `updated` date to the release date.

## 4. Optional: review facts parsed before this change

Facts parsed before WP-07 may still hold a date of birth, visa, salary or id line. The scorer now drops such lines from its prompt, but a confirmed one can still be cited in a tailored line or a drafted answer. To see them, run in the Railway Postgres query tab:

```sql
select user_id, id, confirmed, kind, text from facts
where text ~* '(date of birth|\mdob\M|\mvisa\M|sponsorship|citizen|\mctc\M|\mlpa\M|salary|passport|\mssn\M|aadhaa?r|disabilit|veteran|gender|ethnicity|marital|religion)'
order by user_id;
```

Unconfirmed rows can be deleted safely (`delete from facts where id in (...) and not confirmed;`). Confirmed rows belong to the user's own profile: leave them, or tell me if you want a one-off notice asking those users to review their facts.
